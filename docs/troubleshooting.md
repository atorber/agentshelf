# 排查

日志写在数据目录的 `logs/agentshelf.log`，不会发到外部服务器。先看设置页的服务状态，或执行：

```bash
agentshelf status
```

服务没启动时，这条命令会打印数据目录并以退出码 1 结束。

## 页面停在「正在启动」

界面会等待本地服务就绪。超时后，页面会提示重新启动。

可以先在仓库根目录执行 `./scripts/dev.sh`，或单独执行 `agentshelf serve`，然后刷新 <http://127.0.0.1:1420>。桌面窗口由 Tauri 拉起后端，优先使用仓库里的 `.venv`。换机器后先执行一次 `./scripts/dev.sh`，或 `pip install -e .`。

## 端口

API 默认使用 8765。这个端口被占用时，会在 8765 到 8865 之间选择空闲端口，并写到数据目录的 `runtime.json`。命令行会读这个文件，不需要手改地址。

界面开发服务器使用 1420。打不开页面时，确认 `./scripts/dev.sh` 或 `npm run dev` 仍在运行。

## 关掉窗口之后服务还在

关闭桌面窗口，只会停止由这个窗口启动的后端。终端里单独运行的 `agentshelf serve`，以及 `./scripts/dev.sh` 在它自己的终端里管理的服务，按各自的方式结束。

结束命令行启动的服务：

```bash
agentshelf stop
```

`./scripts/dev.sh` 占用的终端关掉后，由它启动的服务会一起停止。

## 预览、校验和损坏文件

某个文件预览失败时，产物记录、下载和哈希校验仍然可用。损坏文件不会让整个应用退出。

校验结果不一致时，先不要继续把这份文件当作原件。可以从最近的备份恢复，或重新归档一份你确认过的文件。

## 检索没有结果

- 确认检索词至少有 3 个字符。更短的词走普通匹配，不走全文索引。
- 全文检索包含历史版本。筛选项过严时，先清空项目、标签、来源和格式。
- 「语义」和「混合」需要已经导入并启用本地模型。设置页会写明当前原因，例如缺少依赖或尚未启用。
- 索引还在排队时，设置页的待处理任务数大于 0。失败任务会显示错误。

## 备份恢复失败

恢复前确认选中的是 AgentShelf 生成的 zip。恢复过程会先移开现有数据，失败后再移回。如果设置页显示数据库完整性检查未通过，先停止继续写入，再从一份完好的备份恢复。

恢复会替换当前产物库。开始前可以先再做一份当前数据的备份。

## 当前版本的边界

这些情况属于当前版本的范围，排查时不需要再去找对应开关：

- 没有账号、云同步、远程访问和团队权限。
- 不采集 Agent 的思考过程、执行日志和中间产物。
- 不扫描整个磁盘，只归档你或 Agent 明确提交的文件。
- 语义检索在没有本地模型和可选依赖时不可用。全文检索不受影响。
- 安装包需要在 macOS 和 Windows 上分别构建。仓库提供 dmg 和 nsis 的构建配置，不附带已经编好的安装包。
- 服务不能改成监听局域网地址。

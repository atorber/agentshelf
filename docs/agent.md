# 在 Agent 中使用

AgentShelf 的安装和归档，都通过你发给 Agent 的提示词完成。Agent 负责安装 Skill、打开本机窗口，并把当前这份最终稿交进去。

说一句「把这份最终稿归档到 AgentShelf。」即可。名称、项目、标签和来源由 Agent 根据当前任务填写，不用在提示词里写。思考过程、执行日志和中间文件不会归档。有多份都像最终稿、无法判断是哪一份时，它会先问你。像密钥、令牌或私钥这样的文件，也会先征得你的同意。

## 安装到所有项目

```text
请从 https://github.com/atorber/agentshelf 安装 Skill agentshelf-archive（目录 skill/agentshelf-archive）。安装到我当前使用的 Agent 的用户级 skills 目录，使所有项目可用。安装完成后告诉我安装位置，并打开 AgentShelf。如果打不开，说明原因，不要声称已经打开。
```

每个 Agent 安装一次。Claude Code、Cursor、Codex 以及其他支持 Skill 的 Agent 使用同一份 Skill。

## 归档

```text
把这份最终稿归档到 AgentShelf。
```

Agent 会自行确定要归档的文件，并填上这些信息：

| 信息 | 从哪里来 |
|---|---|
| 名称 | 文档标题；没有标题时用文件名 |
| 项目 | 当前项目 |
| 标签 | 根据内容归纳的几个短标签 |
| 来源 | 正在使用的 Agent |

归档成功后，它会告诉你产物名称、编号、版本，以及填上的项目、标签和来源。编号可以以后用来继续追加版本。要改名称、项目或标签时，在窗口详情里保存即可，不会因此产生新版本。

你另外说了名称、项目或标签时，以你说的为准。同一份成果里的多个文件会放进同一份产物。彼此独立的成果才会分开归档，并分别告诉你结果。

## 相同内容

Agent 发现库里已经有相同内容时，会列出候选产物。你回复其中一种：

```text
新建一份产物，不要并到已有记录上。
```

```text
追加到产物「系统架构设计」，作为新版本。
```

## 查找以前的成果

```text
在 AgentShelf 里查找「系统架构」，告诉我产物名称、编号、项目和当前版本。
```

找到之后，可以让它打开对应版本，或把某一份历史版本恢复成新的当前版本：

```text
把「系统架构设计」的上一版恢复为新的当前版本。原来的版本保留。
```

## 它会遵守的规则

- 只提交当前任务里准备留下的最终成果。
- 名称、项目、标签和来源自行填写，不会为此向你提问。
- 按 AgentShelf 实际返回的结果汇报，没有成功时不会说已经归档。
- 不按文件名猜测并覆盖已有产物。
- 不把思考过程、执行日志和中间文件放进库里。

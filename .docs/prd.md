# Agent Artifact Hub — V1.1 研发基线修订

## 一、已确定的产品决策

| 项目 | 最终决策 |
|---|---|
| 支持平台 | macOS、Windows |
| 用户定位 | 个人用户的日常 AI 最终产物管理 |
| 归档入口 | 共享 Skill 归档 + Web UI 手动上传 |
| 部署方式 | 本地运行，不依赖云端服务 |
| 数据存储 | 本地文件系统 + SQLite |
| 基础检索 | 本地全文搜索、元数据过滤 |
| 智能检索 | 采用本地模型，可选启用 |
| Agent 接入 | 统一 CLI/API 协议，针对不同 Agent 提供适配 |
| 中间过程采集 | 不采集 Agent 思考过程、执行日志和中间产物 |
| MVP 目标 | 实现稳定的个人产物仓库及多格式交互检索 |

## 二、跨平台技术架构调整

### 2.1 架构要求

采用跨平台桌面应用方案，建议使用：

- 前端：React + TypeScript。
- 桌面容器：Tauri 2。
- 后端服务：Python + FastAPI。
- 数据库：SQLite + FTS5。
- 文件存储：本地文件系统。
- CLI：Python Typer。
- 后台任务：本地任务队列与 Worker。

Tauri 负责桌面窗口、应用生命周期、系统集成及安装包；Python 后端负责业务逻辑、文件存储、索引和格式解析。

**实现要求：** 桌面应用应负责启动和管理本地后端进程，不要求用户手动打开终端启动服务。关闭应用时，应优雅停止后台任务；重新启动后，能够恢复未完成的任务。

### 2.2 进程关系

```text
Agent / 手动上传
        |
        v
Artifact Skill / CLI / Web UI
        |
        v
桌面应用与本地服务管理
        |
        v
本地 FastAPI 服务
        |
   +----+-----+
   |          |
   v          v
SQLite    文件对象存储
   |
   v
本地全文索引 / 格式解析 / 可选本地向量索引
```

桌面 UI 与本地 API 之间只通过受控的本地接口通信。CLI 和 Skill 也调用同一套 API，不能绕过业务层直接操作数据库。

### 2.3 macOS 和 Windows 的差异处理

- 所有路径使用跨平台路径库处理，不自行拼接 `/` 或 `\`。
- 应用数据目录通过操作系统标准 API 获取。
- 不假设两个系统的文件权限、进程启动和文件锁行为完全一致。
- 后端服务应监听回环地址，不默认开放局域网访问。
- 为两个平台分别提供安装、升级、卸载和故障诊断流程。
- 对文件锁、原子重命名、磁盘空间不足和异常退出分别进行测试。
- 数据目录位置应允许用户在设置中查看，后续可支持迁移。

推荐将桌面端的 UI 与 Python 服务封装为统一安装产品，但应先通过技术验证确定打包、升级及进程管理方案，再进入大规模功能开发。

## 三、完全离线的技术要求

### 3.1 离线定义

“完全离线”是指产品在正常使用过程中，不需要互联网连接，不将产物、元数据、搜索内容或使用记录发送到外部服务。

必须满足：

1. 不依赖云端 API 才能启动。
2. 不依赖云端 API 才能归档和预览文件。
3. 不依赖外部搜索服务完成全文检索。
4. 不从 CDN 加载前端脚本、字体、图标或样式。
5. 不自动向外部服务器发送遥测、分析或错误报告。
6. Skill、CLI、API 和本地检索均能在断网状态下工作。
7. 语义搜索不得强制调用外部 Embedding 或大语言模型服务。

### 3.2 本地智能检索

MVP 默认采用传统全文搜索与元数据过滤，确保离线基础能力可靠。

语义搜索作为可选模块，使用本地 Embedding 模型。模型资源可通过随安装包分发或用户主动导入的方式提供。

需要注意：

- 模型文件体积可能较大，不应未经评估就全部打进主安装包。
- 用户没有安装或启用本地模型时，其他功能必须完整可用。
- 模型下载、更新和导入都必须由用户明确发起。
- 若提供模型导入功能，需校验文件完整性、兼容性和模型版本。
- 语义索引保存在本地，可删除和重新构建。
- 应在设置页明确显示模型状态及语义检索是否启用。

### 3.3 离线验收

测试环境应在网络访问被禁用的情况下验证：

- 首次启动和应用初始化。
- 手动上传文件。
- Skill 与 CLI 归档。
- 全文搜索与筛选。
- PDF、Markdown、图片、CSV、JSON 预览。
- 版本查看与恢复。
- 本地备份与恢复。
- 已启用本地模型时的语义搜索。

任何核心功能不得因外部网络不可用而失效。

## 四、双归档入口设计

### 4.1 Skill 归档

共享 Skill 负责识别最终产物、准备元数据并调用本地服务。

基本流程：

1. Agent 完成任务。
2. Skill 根据规则识别最终成果。
3. 用户明确指定或规则允许时，选取需要归档的文件。
4. Skill 调用本地 CLI/API。
5. Hub 保存文件、生成哈希、建立版本和元数据。
6. Hub 返回归档结果。
7. Skill 只根据实际返回状态向用户报告结果。

Skill 不负责直接修改存储目录，也不允许通过文件名猜测并覆盖已有产物。

### 4.2 Web UI 手动上传

产物库必须提供独立的手动上传入口，支持：

- 点击选择文件。
- 拖拽上传。
- 多文件批量上传。
- 上传进度和失败原因展示。
- 上传前编辑名称、描述、项目和标签。
- 上传完成后跳转到产物详情。
- 同内容重复上传的提示。
- 对已有产物创建新版本或创建新产物的明确选择。

对多个文件的上传，应逐个记录处理结果。部分文件失败时，不应将所有已成功文件回滚或误报失败。

### 4.3 两个入口使用同一业务规则

Skill 归档和手动上传必须共享同一套后端逻辑，包括：

- 文件安全校验。
- SHA-256 计算。
- 内容去重。
- 产物身份判断。
- 版本创建。
- 元数据校验。
- 索引任务创建。
- 错误处理。

禁止在前端或 Skill 中单独实现一套与后端不一致的版本规则。

## 五、个人用户场景下的范围控制

首版不引入团队协作、租户管理和复杂权限体系，优先优化个人用户的易用性。

### 5.1 必须具备

- 一键打开应用。
- 直观的文件上传入口。
- 清晰的产物库与搜索页面。
- 常见格式的直接预览。
- 项目、标签和来源 Agent 管理。
- 版本历史和恢复。
- 本地存储空间查看。
- 备份与恢复。
- 可查看的服务状态和错误提示。
- 基础的 Skill 安装说明。

### 5.2 不纳入首版

- 多用户共享空间。
- 云端同步。
- 远程访问。
- Agent 执行过程管理。
- 强制依赖本地大语言模型。
- 大规模分布式索引。
- 自动扫描整个磁盘。
- 无用户确认的敏感文件归档。

## 六、更新后的 MVP 验收标准

### A. 平台验收

- 在受支持的 macOS 版本上可以安装、启动和卸载。
- 在受支持的 Windows 版本上可以安装、启动和卸载。
- 应用能够自动启动本地服务。
- 关闭和重启应用后，已有数据保持完整。
- 两个平台均通过核心功能自动化测试。

### B. 离线验收

- 断网后可启动应用并使用核心功能。
- 无外部 API、CDN 或云端数据库依赖。
- 网络监测未发现未经授权的外发请求。
- 本地索引、备份和恢复可独立运行。
- 未启用本地模型时，系统仍具备完整的基础检索能力。

### C. 归档验收

- 手动上传与 Skill 归档得到一致的产物管理结果。
- 支持批量上传和逐文件错误反馈。
- 重复内容不重复保存物理文件。
- 产物身份不只由文件名决定。
- 未经确认的模糊身份匹配不会覆盖已有产物。
- 原始文件可完整下载并通过哈希校验。

### D. 多格式交互验收

- PDF、Markdown、TXT、图片、CSV、JSON 均有可用的直接预览。
- 搜索结果可跳转到对应产物。
- 支持的格式能够展示命中片段或定位信息。
- 不支持的格式有明确的降级预览和下载入口。
- 恶意或损坏文件不会导致应用整体崩溃。

### E. 交付验收

- 提供 macOS 与 Windows 安装包。
- 提供统一的 CLI、Skill 和 API 文档。
- 提供本地备份及恢复工具。
- 提供自动化测试报告。
- 提供离线运行验证记录。
- 提供已知限制和故障排查文档。

## 七、开发前必须完成的技术验证

正式进入完整开发前，先完成一个跨平台技术 Spike：

1. Tauri 能否稳定启动和关闭 Python 后端。
2. macOS 和 Windows 的打包方式是否满足交付要求。
3. 本地 API 的访问令牌能否安全管理。
4. SQLite 数据库与对象存储能否在异常退出后恢复。
5. 离线环境下是否不存在隐藏的外部依赖。
6. PDF、图片、CSV 和 JSON 预览器是否可以安全运行。
7. CLI 能否在应用运行时连接本地服务并完成归档。

技术 Spike 验收通过后，再正式启动归档、版本、预览、搜索和 Skill 的并行开发。

**最终研发原则：先保证跨平台安装、完全离线和数据安全，再实现丰富的格式交互与检索能力。**
